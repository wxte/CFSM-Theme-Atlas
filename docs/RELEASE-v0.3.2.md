# WXT Atlas v0.3.2

本版在 v0.3.1 完整主题上修复真实反馈，不修改 GitHub 或线上配置。

## 修复和调整

- 节点和 Drawer 状态条按采样时间锁定，数据更新时不重建控件，保留选中高亮、说明和键盘焦点。提供“返回实时”和 Esc；已移出最近60格的选中样本仍显示锁定时间，不偷偷跳到最新样本。
- 当前标签页刷新后恢复最近60次资源上报、最近网络观测、节点选中采样、筛选、排序和网络时间范围。使用限量 sessionStorage（最多100节点，资源缓存最长24小时），不是跨设备数据库；关闭标签页或清除浏览器数据后不保证保留。缓存不可用时仍可正常显示实时数据。
- 修复命令面板“查看最近活动”：延后执行动作，避免原点击冒泡立刻关闭刚打开的活动面板。保留顶栏搜索。
- 微型折线统一基线与尺寸，CPU固定0–100%，上下行共用速率刻度，显示完整标签并区分颜色。不足60次上报时在右侧按实际点数占位，避免两点横跨整张图。数据缺失和长间隔断线，不加伪造平滑点。
- Drawer 趋势显示在详情上方，实时更新不替换正在操作的状态条。
- 页脚和所有运行时 URL 统一 v0.3.2；根目录增强文件与 assets 副本同步。

## 24小时 / 7天历史

已核实并接入 CFSM 的 `/api/history/all?id=...&hours=...`，网络页默认24H，支持1H / 2H / 6H / 24H / 7D。

线上只读验证：一个公开节点的24小时请求返回200及120个历史点；7天请求未登录返回401。后端源码明确规定大于24小时需要认证。因此，本版7D会使用当前站点已有的后台登录凭据；没有登录则显示“7 天历史需要登录 CFSM 后台”，不会绕过权限，也不会用两小时数据伪装七天。

历史来自服务端，刷新重新读取；不是要求网页一直开着七天。只在进入网络页时加载，最多3个并发请求，同一范围5分钟内复用。手动刷新/点击失败提示可重试。快速切换范围时旧请求不会覆盖新范围。

每个运营商显示60个时间段状态格。空时段显示缺失；高延迟/丢包、100%丢包分别着色。点击曲线或方向键锁定时间并高亮，返回实时解除。服务端历史可能已聚合或降采样，不等于逐秒原始记录，也不推导连续在线率。服务端历史覆盖的时段不重复混入列表历史，末尾只追加更新的实时观测。

布局参考 [Uptime Kuma](https://github.com/louislam/uptime-kuma) 的紧凑状态格与交互高亮思路；没有复制其 Vue 运行时或添加图表库。仍为原生 JS/CSS、无外部 CDN、无新增运行时依赖。

## 覆盖方式

将完整 ZIP 内的文件和目录覆盖仓库根目录，无需执行历史 apply-v0.3.0.mjs。该旧脚本只作历史资料，运行会回退版本信息。部署后页脚应显示 v0.3.2。
