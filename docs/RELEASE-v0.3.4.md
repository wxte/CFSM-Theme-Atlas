# WXT Atlas v0.3.4

## 1H / 2H 状态格“无数据”

截图中的41个历史点被v0.3.3强制分进60个时间段，所以即使曲线连续，也会出现交替空格。它们是时间桶没有采样，不是接口完全没有返回数据。此次取消这种容易误解的展示：

- 不超过60个历史点时，每格对应一个真实观测；41点显示41格。
- 超过60点时合并相邻观测成最多60格，保留最严重的丢包/延迟状态。
- 不插值、不填充绿色；指标本身缺失仍标为未知。
- 状态格不是等间隔时间轴或连续在线率，曲线继续按真实时间定位并保留长间隔断线。
- 点击状态格优先定位其中较严重的真实观测；单点格也能正确高亮。
- 旧版人工空时间格的网络锁定缓存升级后清除一次，避免继续显示旧的“无数据”提示；节点锁定与刷新缓存保留。

## 性能

确认了重复工作，但没有证据据此认定用户设备上整站性能严重下降。

已优化：资源图与网络状态格分开更新；数据未变时跳过DOM写入；CPU更新不再重写60格和时间说明；相同资源上报不重复标记变更；历史未变不重复保存；复用时间格式器；缓存网络历史预处理；曲线路径由嵌套扫描改为单次遍历。

本地Chrome无头浏览器局部基准，8节点、每节点60条记录、连续30轮更新，比较v0.3.3和v0.3.4：

| 场景 | v0.3.3 | v0.3.4 |
|---|---:|---:|
| 数据未变化的渲染函数耗时 | 50.2ms | 0.1ms |
| 对应DOM变更记录 | 46,560 | 0 |
| 仅资源变化的渲染函数耗时 | 46.8ms | 9.8ms |
| 对应DOM变更记录 | 46,560 | 2,400 |

这是特定渲染函数的局部基准，不是整站加载时间、手机帧率或后端负载测试；不能把约79%的局部耗时下降当作整站提速比例。新增长历史查询仍只在网络页加载，最多3并发、5分钟缓存；没有增加轮询频率。
